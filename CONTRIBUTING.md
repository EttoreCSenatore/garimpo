# Contributing to Garimpo

Thanks for helping. Garimpo is a polite catalog scraper, REST API and chat search; docs live at https://ettorecsenatore.github.io/garimpo/ (English and Portuguese).

- **Bugs and ideas:** open an [issue](https://github.com/EttoreCSenatore/garimpo/issues) with what you did, what you expected and what happened. Security problems go to [SECURITY.md](SECURITY.md) instead, never a public issue.
- **Code:** fork, branch, open a pull request. `main` only takes pull requests with green checks (backend, frontend, docker, CodeQL).
- **Two languages:** a change to user-facing docs changes both `website/docs/` and `website/i18n/pt-BR/...`.
- **Responsible use:** never point the scraper at a site you have no permission to scrape, and never weaken the throttle, the robots.txt rules or the image-proxy allow-list. See [Responsible use](https://ettorecsenatore.github.io/garimpo/responsible-use).

## Set up

```bash
./deploy/lock.sh                      # only when you change requirements*.in (needs Docker)
python -m venv .venv
.venv/bin/pip install --require-hashes -r requirements-dev.txt
.venv/bin/python -m pytest tests --cov=app     # coverage floor: see pyproject.toml
.venv/bin/ruff check . && .venv/bin/ruff format --check .
cd frontend && npm ci && npx tsc --noEmit && npm run build
```

Try it with demo data and a throwaway database: `./scripts/demo.sh`. Never run tests or scripts against your real `garimpo.db`: tests use a temporary database through `tests/conftest.py`; for ad-hoc scripts set `DATABASE_URL` to a scratch copy.

## Dependencies

Direct dependencies are listed in `requirements.in` (runtime) and `requirements-dev.in` (tools). The hashed locks `requirements.txt` and `requirements-dev.txt` are generated by `deploy/lock.sh`; CI fails when they are stale. GitHub Actions are pinned to a commit SHA with the tag in a comment, and Dependabot updates both.
